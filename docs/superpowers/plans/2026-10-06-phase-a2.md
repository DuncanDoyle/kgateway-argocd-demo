# Phase A2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend product A's ArgoCD health checks from two `gateway.kgateway.dev` kinds to five, from two hand-maintained Lua scripts to one shared script per status shape, and ship product A's ConfigMap package.

**Architecture:** argo-cd's Lua VM cannot share code between checks, so logic is shared by making the scripts byte-identical across kinds of the same status shape — messages read `obj.kind` rather than hardcoding the name. The repo holds one script per shape; `hack/extract-testdata.sh` assembles a per-kind `resource_customizations/` tree from them, so divergence is structurally impossible rather than merely discouraged. New kinds are exercised by a third ArgoCD Application that exists to generate status for capture, leaving the demo narrative untouched.

**Tech Stack:** Lua 5.1 (gopher-lua, as embedded by argo-cd), bash, kubectl, Helm, yq v4, Go (to run argo-cd's test harness), kgateway v2.4.5, Gateway API v1.6.1, Argo CD chart 10.9.2.

**Spec:** `docs/superpowers/specs/2026-10-06-phase2-design.md`

## Global Constraints

- **Product A is a public OSS artifact.** No file, comment, commit message, doc or PR text produced by this plan may mention Solo Enterprise for kgateway, link to internal Solo repositories, name a customer, or cite an internal tracker ID. Product B is out of scope entirely.
- Repo: `~/Development/github/kgateway-argocd-demo`, branch `main`. The argo-cd fork clone is `~/Development/github/argo-cd`, branch `feat/kgateway-health-checks` (local only, based on `upstream/master` `1db740c`).
- Five kinds ship: `Backend`, `TrafficPolicy`, `ListenerPolicy`, `BackendConfigPolicy`, `DirectResponse`.
- Three kinds are excluded and must be named with reasons wherever coverage is described: `GatewayParameters` (no status implemented), `HTTPListenerPolicy` (deprecated in 2.4.x, absent from `main`), `GatewayExtension` (writes no status — verified live on v2.4.5, not inferred from the schema).
- `kgateway.dev/kgateway` is the exact `controllerName` string ancestors are filtered on.
- **Fixture count: 21.** 11 existing, plus 6 for the three new kinds (healthy and one observed non-healthy state each), plus 4 pinning Review Focus items: `no_kind`, `no_status`, `foreign_controller` on a new kind, and `wrong_shape`. - Fixtures are **captured** from a live cluster. A fixture that cannot be captured may be **derived** from a real capture with a header disclosing exactly what was substituted. Nothing is fabricated.
- Broken manifests must pass CRD admission and fail at translation. An admission-rejected manifest produces no resource and therefore no status.
- `out/` is gitignored and holds only generated content. Authored content lives under `healthchecks/`.
- **Pushes are run by the coordinator, not by implementers** — the permission classifier denies them in subagent context.
- Cluster: minikube profile `kgw-argocd`, already running with both existing Applications synced.

## Review Focus

Input classes the spec implies but which no task's own feature tests would otherwise exercise, most likely to bite first:

1. **A resource with no `kind` field.** The refactor makes every message depend on `obj.kind`; in Lua `"Waiting for " .. nil` raises an error, which breaks health evaluation for that resource entirely rather than degrading gracefully. Pinned in Task 1.
2. **A kind wired to the wrong shared script** — e.g. an ancestors kind given the conditions script. It would report `Progressing` forever and look like a controller bug. Pinned in Task 3.
3. **A new kind whose ancestors carry a foreign `controllerName`.** Covered for `TrafficPolicy` by an existing fixture, but nothing proves the shared script still filters once copied elsewhere. Pinned in Task 3.
4. **A conditions-shaped resource with no `status` key at all**, as between creation and the controller's first write. It must report Progressing, never Healthy — a resource nobody has judged is not a healthy one. Pinned in Task 1.
5. **A kind missing from the sync mapping.** A new kind silently gets no script and no subtests — the vacuous-pass trap that already bit phase 1 twice. Pinned in Task 1.

- [ ] **Step 2: Add the nil-safe kind helper to both scripts**

Insert immediately after the `local hs = {}` line in **both** files. This is the
guard for Review Focus #1 — `obj.kind` is present on every object ArgoCD passes,
but concatenating `nil` raises a Lua error that would break health evaluation
rather than degrade, and the fallback costs nothing.

```lua
-- Messages read obj.kind so this one script serves every kind of this status
-- shape byte-identically. obj.kind is always set on a real cluster object, but
-- concatenating nil raises a Lua error that would break health evaluation, so
-- fall back rather than trust it.
local function kindName()
  if obj ~= nil and obj.kind ~= nil and obj.kind ~= "" then
    return obj.kind
  end
  return "resource"
end
```

- [ ] **Step 5: Teach the extract script the kind-to-shape mapping**

Create `hack/kind-shapes.sh` — a single definition both the extract and render
scripts source, so the mapping never exists in two places:

```bash
#!/usr/bin/env bash
# Kind -> status shape. One shared script serves every kind of a shape; the
# copies are assembled here rather than hand-maintained, so they cannot drift.
# A kind missing from these lists silently gets no health.lua, and argo-cd's
# harness then reports "no tests to run" rather than failing — so Step 7's
# check exists to catch exactly that.
ANCESTORS_KINDS="TrafficPolicy"
CONDITIONS_KINDS="Backend"
```

Source it from `hack/extract-testdata.sh`, immediately after the `OUT=`
assignment:

```bash
source ./hack/kind-shapes.sh
```

Then replace the existing block that copies `health.lua`/`health_test.yaml` into
`out/` with:

```bash
install_shape() {
  local shape="$1"; shift
  for kind in "$@"; do
    mkdir -p "${OUT}/${kind}"
    cp "healthchecks/lua/${shape}/health.lua" "${OUT}/${kind}/health.lua"
    cp "healthchecks/lua/${kind}/health_test.yaml" "${OUT}/${kind}/health_test.yaml"
    # testdata/ MUST be copied: health_test.yaml's inputPath entries are
    # relative to the kind's directory in the generated tree, so omitting it
    # leaves every test pointing at a file that does not exist.
    cp -R "healthchecks/lua/${kind}/testdata" "${OUT}/${kind}/testdata"
  done
}
install_shape ancestors ${ANCESTORS_KINDS}
install_shape conditions ${CONDITIONS_KINDS}

# Guard against a kind being added to healthchecks/lua/ but forgotten in the
# mapping. Iterate the AUTHORED source directories, not the generated ones:
# a kind missing from the mapping creates no output directory, so checking
# the output cannot see it. argo-cd's harness generates no subtests for a
# directory without health.lua and reports a vacuous pass, so this is the
# only thing standing between a forgotten kind and silent non-coverage.
MAPPED=" ${ANCESTORS_KINDS} ${CONDITIONS_KINDS} "
for src in healthchecks/lua/*/; do
  kind=$(basename "$src")
  # Shape directories hold scripts, not fixtures; skip them.
  [ -f "${src}/health_test.yaml" ] || continue
  case "${MAPPED}" in
    *" ${kind} "*) ;;
    *) echo "ERROR: ${kind} has fixtures but is missing from the shape mapping in hack/kind-shapes.sh" >&2; exit 1 ;;
  esac
  for required in health.lua health_test.yaml testdata; do
    [ -e "${OUT}/${kind}/${required}" ] || { echo "ERROR: ${OUT}/${kind}/${required} missing" >&2; exit 1; }
  done
done
```

## Notes for the executor

**Task 2 is allowed to invalidate this plan.** Every mechanism in it is
predicted from a CRD schema, not observed. Phase 1's equivalent probe found two
API errors that would otherwise have shipped as broken fixtures. If a kind's
Degraded state proves unreachable, record it as a finding and check whether
unreachable is simply *correct* for that kind before calling it a bug.

**Count subtests, never trust `ok`.** argo-cd's harness generates no subtests
for a directory without a `health.lua` and reports a vacuous pass. Every test
step here counts individual PASS lines for that reason.

**Messages come from the controller.** Where a step says `<observed …>`, read
the value out of the captured fixture. A message mismatch means the test is
wrong, not the controller.

**Nothing in this plan publishes anything.** Task 6 prepares; the coordinator
pushes and opens the PR after review.
